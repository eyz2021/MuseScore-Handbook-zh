MSCORE(1) — 通用命令手册页

名称

mscore, MuseScore4 - MuseScore 4 乐谱编辑器

用法概要

您可以通过键入以下命令从命令行启动 MuseScore：

  • mscore [options] [filename …]（Mac 和 Linux/BSD/Unix）
  • musescore [options] [filename …]（Linux/BSD/Unix）
  • mscore4portable [options] [filename …]（Linux AppImage）
  • MuseScore4.exe [options] [filename …]（Windows）

[options] 和 [filename] 是可选的。为此，MuseScore 可执行文件必须位于 %PATH%（Windows）或 $PATH（Mac 和 Linux）中。如果不在，请参见恢复出厂设置，了解如何在各种受支持的平台上从命令行查找和执行 MuseScore 可执行文件的详细说明。

更详细的用法概要如下：

mscore [-deFfhIiLmnOPRstvw]\ [-b | --bitrate bitrate]\ [-c | --config-folder pathname]\ [-D | --monitor-resolution DPI]\ [-d | --debug]\ [-E | --install-extension extension file]\ [-e | --experimental]\ [-F | --factory-settings]\ [-f | --force]\ [-h | -? | --help]\ [-I | --dump-midi-in]\ [-i | --load-icons]\ [-j | --job file.json]\ [-L | --layout-debug]\ [-M | --midi-operations file]\ [-m | --no-midi]\ [-n | --new-score]\ [-O | --dump-midi-out]\ [-o | --export-to file]\ [-P | --export-score-parts]\ [-p | --plugin name]\ [-R | --revert-settings]\ [-r | --image-resolution DPI]\ [-S | --style style]\ [-s | --no-synthesizer]\ [-T | --trim-image margin]\ [-t | --test-mode]\ [-v | --version]\ [-w | --no-webview]\ [-x | --gui-scaling factor]\ [--diff]\ [--long-version]\ [--no-fallback-font]\ [--raw-diff]\ [--run-test-script]\ [--score-media]\ [--score-meta]\ [--highlight-config]\ [--score-parts]\ [--score-parts-pdf]\ [--score-transpose]\ [--sound-profile]\ [--source-update]\ [--template-mode]\ [file ...]

描述

MuseScore 是一款自由开源的所见即所得 (WYSIWYG)、跨平台、多语言音乐创作和记谱软件，在 GNU 通用公共许可证 (GPLv3) 下发布。

在没有任何额外选项的情况下运行 mscore 会启动完整的图形化 MuseScore 程序，并打开命令行上指定的任何文件。

选项如下：

  • -b | --bitrate bitrate

以 kbit/s 为单位设置 MP3 输出比特率 * -c | --config-folder pathname

覆盖配置和设置目录 * -D | --monitor-resolution DPI

指定显示器分辨率（覆盖自动检测） * -d | --debug

以调试模式启动 MuseScore * -E | --install-extension extension file

安装扩展文件；除非同时指定 -e，否则默认加载音色库 * -e | --experimental

启用实验性功能 * -F | --factory-settings

仅使用标准内置预设（“出厂设置”）并删除用户偏好设置；与 -R 选项对比（另请参见恢复出厂设置） * -f | --force

忽略“转换器模式”中的乐谱损坏和版本不匹配警告 * -h | -? | --help

显示调用说明的概述（在 Windows 上无效） * -I | --dump-midi-in

在控制台显示所有 MIDI 输入 * -i | --load-icons

从文件系统加载图标；如果您想编辑 MuseScore 图标并预览更改，这很有用 * -j | --job file.json

处理转换作业（参见下方的示例） * -L | --layout-debug

以排版调试模式启动 MuseScore * -M | --midi-operations file

指定 MIDI 导入操作文件（参见下方的示例） * -m | --no-midi

禁用 MIDI 输入 * -n | --new-score

无论用户偏好设置中是否启用，都从“新建乐谱”向导开始 * -O | --dump-midi-out

在控制台显示所有 MIDI 输出 * -o | --export-to file

将给定（或当前打开的）文件导出到指定的输出文件。文件类型取决于给定文件名的扩展名。此选项切换到“转换器模式”并避开图形用户界面。 * -P | --export-score-parts

使用 -o 选项转换为 PDF 时，将每个分谱的页面附加到创建的 PDF 文件中。如果乐谱没有分谱，将自动临时生成所有默认分谱。 * -p | --plugin name

执行指定的插件 * -R | --revert-settings

仅使用标准内置预设（“出厂设置”），但不删除用户偏好设置；与 -F 选项对比 * -r | --image-resolution DPI

设置转换为 PNG 文件的图像分辨率。默认值：300 DPI * -S | --style style

先加载样式文件；与 -o 选项一起使用时很有用 * -s | --no-synthesizer

禁用集成的软件合成器 * -T | --trim-image margin

裁剪导出的 PNG 和 SVG 图像，以去除乐谱周围的空白。指定的margin（以像素为单位）将被保留（使用 0 获得紧密裁剪的图像）。导出到 SVG 时，此选项仅适用于单页乐谱。 * -t | --test-mode

为所有文件设置测试模式标志，包括 --template-mode * -v | --version

显示应用程序的名称和版本，而不启动图形用户界面（在 Windows 上无效） * -w | --no-webview

禁用开始中心中的 Web 视图组件 * -x | --gui-scaling factor

按指定的factor缩放乐谱显示和其他 GUI 元素；用于高分辨率显示器 * --diff

打印给定乐谱之间的条件差异 * --long-version

显示应用程序的完整名称、版本和 git 修订号，而不启动图形用户界面（在 Windows 上无效） * --no-fallback-font

不使用 Bravura 作为后备音乐字体 * --raw-diff

打印给定乐谱之间的原始差异 * --run-test-script

运行命令行参数中列出的脚本测试 * --score-media

将给定乐谱的所有媒体（MP3 除外）作为单个 JSON 文档导出到标准输出 * --highlight-config

将高亮设置为 svg，从给定乐谱生成 * --score-meta

将乐谱元数据导出为 JSON 文档并打印到标准输出 * --score-parts

为给定乐谱生成分谱数据，并将其保存到单独的 mscz 文件 * --score-parts-pdf

为给定乐谱生成分谱数据，并将其作为单个 JSON 文档导出到标准输出 * --score-transpose

移调给定乐谱并将数据导出到单个 JSON 文件，打印到标准输出 * --sound-profile sound-profile

与 '-o .mp3' 或 '-j ' 一起使用，覆盖给定乐谱中的声音配置文件。\ 可能的值："MuseScore Basic"、"Muse Sounds" * --source-update

更新给定乐谱中的源 * --template-mode

以模板模式保存文件（例如，不带页面大小）

MuseScore 还支持自动的 Qt 命令行选项。

批处理转换作业 JSON 格式

-j 选项的参数必须是包含符合以下规范的有效 JSON 文档的文件的路径名：

  • 顶层元素必须是一个 JSONArray，可以为空。
  • 每个数组元素必须是一个 JSONObject，包含以下键：
  • in：值是输入文件名（要转换的乐谱），作为 JSONString。
  • plugin：值是插件文件名（带有 .qml 扩展名），将从全局或每用户插件路径读取，并在转换输出发生之前执行，作为 JSONString。可选，但 plugin 和 out 中必须至少给出一个。
  • out：值是转换输出目标，定义如下。可选，但 plugin 和 out 中必须至少给出一个。
  • 转换输出目标可以是文件名（带扩展名，决定要转换成的格式），作为 JSONString。
  • 转换输出目标可以是文件名的 JSONArray，作为 JSONString，如上所述，这将导致乐谱被顺序写入多个输出文件（多种输出格式），而不会在中间关闭、重新打开和重新处理。
  • 如果转换输出目标是一个 JSONArray，其一个或多个元素也可以分别是一个由两个 JSONString 组成的 JSONArray（在以下描述中称为前半部分和后半部分）。这将导致分谱提取：对于每个这样的二元组，乐谱的所有现存分谱将被单独保存，文件名由前半部分、分谱名称（标题）和后半部分拼接而成。结果字符串必须是有效的文件名（带扩展名，决定输出格式）。如果乐谱没有定义分谱（摘录），这将被静默忽略，不会报错。
  • 有效的输出文件扩展名有：

  • flac

    自由无损音频编解码器（压缩音频） * metajson

    各种乐谱元数据 (JSON) * mid

    标准 MIDI 文件 * midi

    标准 MIDI 文件 * mlog

    内部文件完整性检查日志 (JSON) * mp3

    MPEG Layer III（有损压缩音频） * mpos

    小节位置 (XML) * mscx

    未压缩的 MuseScore 文件 * mscz

    压缩的 MuseScore 文件 * musicxml

    未压缩的 MusicXML 文件 * mxl

    压缩的 MusicXML 文件 * ogg

    OGG Vorbis（有损压缩音频） * pdf

    便携式文档文件（打印） * png

    便携式网络图形（图像）——将生成单独的文件，每个乐谱页一个，在文件扩展名之前放置一个连字符减号后跟页码。 * spos

    分段位置 (XML) * svg

    可缩放矢量图形（图像） * wav

    RIFF 波形（未压缩音频） * xml

    未压缩的 MusicXML 文件

环境

  • SKIP_LIBJACK

设置此项（值无关紧要）以跳过 JACK Audio Connection Kit 库的初始化，以防它引起问题。 * XDG_CONFIG_HOME

用户配置位置；如果未设置，默认为 ~/.config。 * XDG_DATA_HOME

用户数据位置；如果未设置，默认为 ~/.local/share。

请注意，MuseScore 还支持常规的 Qt 环境变量，例如 QT_QPA_GENERIC_PLUGINS、QT_QPA_PLATFORM、QT_QPA_PLATFORMTHEME、QT_QPA_PLATFORM_PLUGIN_PATH、QT_STYLE_OVERRIDE、DISPLAY 等。

文件

/usr/share/mscore-4.0/ 包含应用程序支持数据（演示、乐器、本地化、系统级插件、音色库、样式、和弦、模板和壁纸）。在 Debian 软件包中，系统级音色库分别安装到 /usr/share/sounds/sf2/、/usr/share/sounds/sf3/ 或 /usr/share/sounds/sfz/。

每用户数据（扩展、插件、音色库、样式、模板）和文件（图像、乐谱）通常安装到 ~/MuseScore4/ 下的子目录中，但可以在配置中更改。请注意，快照版、alpha 版和 beta 版在所有这些路径中使用 MuseScore4Development 而不是 MuseScore4。

$XDG_CONFIG_HOME/MuseScore/MuseScore4.ini 包含用户偏好设置、最近使用的文件列表及其位置、窗口大小和位置等。参见上方开发版本路径。

$XDG_DATA_HOME/data/MuseScore/MuseScore4/ 包含从程序内下载的更新本地化文件、插件信息、缓存的乐谱、musescore.com 社区站点的凭据、会话信息、合成器设置、自定义调号和拍号以及快捷键。参见上方开发版本路径。

示例

从命令行将乐谱转换为 PDF

mscore -o 'My Score.pdf' 'My Score.mscz'

运行转换多个文档的批处理作业

mscore -j job.json

这需要假设当前工作目录中存在一个 job.json 文件，其内容类似于以下：

[
    {
        "in": "MyScore1.mscz",
        "out": "MyScore1.pdf"
    },
    {
        "in": "MyScore2.mscz",
        "plugin": "colornotes.qml",
        "out": [
            "MyScore2-notecolors.pdf",
            "MyScore2-notecolors.svg"
        ]
    },
    {
        "in": "MyScore3.mscz",
        "out": [
            "MyScore3.pdf",
            "MyScore3.musicxml",
            "MyScore3.mid",
            [
                "MyScore3 (",
                " part).pdf"
            ]
        ]
    }
]

如果 MyScore3.mscz 包含摘录（乐器分谱），则上述语法会导致生成诸如“MyScore3 (Violin part).pdf”之类的文件，同时生成指挥的 PDF 和 MusicXML 文件，以及带有完整管弦乐声音的 MIDI 文件。如果 MyScore3.mscz 没有定义摘录，则只会生成指挥的 PDF、MusicXML 和管弦乐 MIDI 文件，而分谱 PDF 的请求会被静默忽略。

标准

MuseScore 尝试实现以下标准：

  • MusicXML 4.0（乐谱交换格式）
  • SF2 (SoundFont 2.01)
  • SF3（带 OGG Vorbis 压缩采样的 SoundFont）
  • SFZ（Sforzato 音色库）
  • SMuFL（标准音乐字体布局 1.4）

历史

MuseScore 于 2002 年从 MusE 音序器分离出来，此后成为最重要的开源记谱软件。

作者

MuseScore 由 MuseScore Limited 等开发。

本手册页最初由 mirabilos <tg@debian.org> 编写。

注意事项

自动的 Qt 命令行选项会在应用程序有机会处理选项之前从参数向量中移除；这意味着像 mscore -S -reverse 这样的调用无法工作，因为 -reverse 会先被 Qt 移除。

缺陷

  • MuseScore Studio 不遵循 /etc/papersize。
  • 查看项目的缺陷跟踪器（参见另请参阅）。
