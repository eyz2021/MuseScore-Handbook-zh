使用 GitBook

概述

组织

GitBook 上的用户内容始终归属于一个组织。就我们而言，那就是 MuseScore。

空间

在组织内，你可以为不同内容创建空间。我们目前有一个名为 English (US) 的空间，用于存放手册的英文源文本。我们稍后会添加更多空间；每种翻译一个空间，如果需要的话也包括 English (GB)（或者我们可以将主空间重命名为 "English"）。

站点 / 文档站点

要使空间对公众可见，必须将其添加到文档站点（即“站点”）。我们目前有一个名为 MuseScore Studio Handbook 的站点。该站点将用于源空间和所有翻译。

现在手册站点已发布，可在以下地址访问：

  • https://musescore.gitbook.io/musescore-studio-handbook（规范站点 URL）
  • https://musescore.gitbook.io/（别名，因为它被设置为该组织的默认站点）
  • https://handbook.musescore.org/（因为我们设置了自定义域名）

当站点处于发布状态时，其空间上的实时编辑将被禁用，因此所有更改都必须通过变更请求（或通过 GitHub，如果启用了 GitHub 同步）进行。

GitHub 同步

空间内的内容可以与 GitHub 仓库同步。在仓库中，内容以 Markdown 文件形式存储，每个父页面或组都有子文件夹。

同步是双向的，因此在任一方所做的编辑都会反映到另一方。这将使我们能够：

  1. 在 GitBook 或 GitHub 上编辑源文本。
  2. 将字符串从 GitHub 上传到 Transifex。
  3. 将翻译从 Transifex 下载到 GitHub。
  4. 将翻译同步回 GitBook。

当 GitHub 同步启用时，实时编辑将被禁用，因此所有更改都必须通过变更请求进行，或在 GitHub 上通过拉取请求或直接向仓库提交进行。

导航

目录 / 目录

屏幕左侧是当前空间中组、页面和子页面的列表。这个列表就是目录（summary）或目录（table of contents）。如果启用了 GitHub 同步，目录会出现在空间根目录下名为 SUMMARY.md 的文件中。

要防止特定页面出现在目录中，请转到页面操作 (⋮) > 隐藏页面。

该页面仍会出现在搜索结果中，任何拥有 URL 的人都可以访问。

页面大纲 / 本页内容

屏幕右侧，“ON THIS PAGE”标签下方，是当前页面上标题的列表。这就是页面大纲。只有一级标题和二级标题会显示在大纲中。

三级标题（不显示在页面大纲中）

要隐藏目录或页面大纲的侧边栏，请转到页面操作 (⋮) > 选项。

目录和页面大纲在其他页面上仍然可见。

页面

你现在正在查看一个页面。这个页面实际上是主页的子页面。也可能存在子子页面，依此类推。

默认情况下，父页面在目录中是折叠的，因此你看不到它们的子页面。当你查看父页面或单击目录中其旁边的展开箭头时，子页面才会显示出来。

组

页面也可以嵌套在组下。组名在目录中以大写字母显示。

与父页面不同，组在目录中始终展开，无法折叠。此外，组不能嵌套在其他组或页面下。

组不是页面，因此不能包含自己的内容。如果你尝试访问组的 URL，GitBook 会将你重定向到组中的第一个页面。

编辑

实时编辑

GitBook 有一种实时编辑模式，你可以直接编辑内容，而无需先创建“分支”。在此模式下，你可以添加、移动、重命名和删除页面，以及编辑现有页面上的内容。

当站点处于发布状态，或 GitHub 同步启用时，实时编辑会被禁用。

如果编辑被禁用，本页提到的许多菜单 (⋮)、选项 (⠿) 和按钮 (+) 将不可用，直到你开始创建变更请求。

变更请求（CR）

当实时编辑被禁用时，进行更改的唯一方式是通过变更请求，即“CR”。这会创建一个个人的“分支”，在该分支上编辑功能是启用的。你的 CR 分支覆盖整个空间，因此如有必要，可以在单个 CR 中编辑多个文件，但只有在更改相关时才应这样做。

编辑完成后，你可以提交 CR 以供审阅，就像 GitHub 拉取请求（PR）一样。与 PR 一样，变更请求始终应有一个有意义的标题来描述所做的更改。理想情况下，标题应使用祈使语气，即它应能补全句子“此变更请求将……”。

CR 名称示例评分评论
"shoogle 的 11 月 21 日更改"1默认 CR 名称。描述性不够。
"节拍调制"2勉强及格。
"添加了节拍调制的图片"3较好，但不是祈使语气。
"添加节拍调制的图片"4这是祈使语气。
"速度：添加节拍调制的图片"5祈使语气，并指明了正在编辑的主题。

一般来说，每个变更请求只应做一件事。这件事可能是：

  • “添加页面：节奏”
  • “将‘拍子’页面重命名为‘拍号’”
  • “Linux 上的安装：删除不必要的细节”
  • “在所有页面上将‘MuseScore 4’替换为‘MuseScore Studio’”

在命名 CR 时，如果你无法避免使用“和”这个词（如“做这件事 和 做那件事”），这表明你应该考虑将编辑拆分到多个 CR 中。

解决冲突

在你等待变更请求（CR）合并期间，它所基于的内容可能在主空间中发生变化（例如，如果其他人的 CR 在你的之前被合并）。如果发生这种情况，GitBook 会提示你更新变更请求以反映新的主内容。

当你单击 CR 中的更新按钮时，GitBook 会提醒你它无法自动解决的任何冲突。如果你更改的块（即段落）在主空间中也发生了更改，就会发生这种情况。此时，GitBook 会并排显示该块的两个版本，并要求你选择保留一个：主版本，或你更改的版本。如有必要，你可以手动编辑该块以合并两个版本的要素。

某些类型的冲突 GitBook 无法识别。例如，如果你的编辑引用了其他内容（如页面上方已有的图片或定义），则应在更新 CR 后检查该内容是否仍然存在。此外，如果你编辑的页面在主空间中被重命名，更新 CR 时你可能会发现自己有两个页面副本，名称和内容各不相同。如果发生这种情况，你将不得不删除其中一个副本，并可能将其部分内容转移到另一个副本中。

每个变更请求都应专注于单个主题。这样可以更快地审阅和合并，从而降低冲突发生的可能性，并使冲突发生后更容易解决。

创建新页面和组

如果你将光标悬停在目录中的现有页面或组上，会出现一个更多操作 (⋮) 按钮，点击后会显示一个菜单，其中包含插入子页面选项。这会在父页面或组下创建一个新的空页面。同样，如果你悬停在目录中页面之间，会出现一个添加 (+) 按钮，使你能在相邻页面之间插入新页面。

要创建组，请使用目录底部的新增选项。此按钮也可用于创建顶级页面（即不是其他页面或组的子页面的页面）。创建后，你可以将新页面或组拖动到目录中的正确位置。

如果启用了 GitHub 同步，并且你在仓库中创建了新的子文件夹或 Markdown 文件，则必须手动将其添加到 SUMMARY.md 中，GitBook 才能感知到它。

从旧手册导入页面

当你将光标悬停在目录中的现有页面或组上时，出现的更多操作 (⋮) 菜单按钮还包含一个导入子页面选项。使用此选项，你可以选择计算机上的 Markdown 或 HTML 文件进行上传，并将其转换为新的子页面。

要创建 Markdown 或 HTML 文件：

  1. 访问旧手册的页面，并使用“编辑”选项。
  2. 复制标题和源文本，并将其粘贴到 https://shoogle.github.io/gitbookify/。
  3. 单击“转换”，并将生成的文件保存到计算机上的某个位置。

进入 GitBook 后，页面可能会有一些问题，例如：

  • 指向其他手册页面的链接已损坏。
  • 图片是从 MuseScore.org “热链”的，而不是上传到 GitBook。
  • 如果导入的是 HTML 而不是 Markdown：
  • \

    元素被错误地导入为二级标题。（\

编辑页面

GitBook 使用基于块的编辑器，与 Squarespace 和较新版本的 Wordpress 有些类似。

内容块

以下各项都会创建一个新块：

  • 段落
  • 标题
  • 列表项
  • 表格行
  • 等等。
展开我 某些块可以嵌套在其他块中，例如本段，它嵌套在一个可展开的部分中。

如果你将光标悬停在现有块上，会显示一个加号 (+) 按钮用于添加新块，以及一个选项 (⠿) 按钮用于当前块。选项按钮也可以被拖动以在页面上重新定位块。

创建块的另一种方法是编辑现有块并按 Enter 或 Return。这通常会在第一个块下方创建一个新的段落块，但也可能创建其他内容，例如新的列表项或表格行。如果是列表项，你可以按 Tab 和 Shift+Tab 来更改嵌套级别，并按 Enter 或 Return 将其转换为普通段落（这仅在块为空时有效）。

在编辑空块时，你可以输入正斜杠 (/) 将其快速转换为不同类型的块。如果块不为空，输入斜杠 (/) 则会显示插入行内内容的选项。
