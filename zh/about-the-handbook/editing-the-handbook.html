文章撰写指南

你想为 MuseScore 4 手册做贡献——太棒了！我们很高兴你的加入。

本页包含一些简明的指南，帮助你开始撰写文章。在编辑手册中的任何内容之前，请仔细阅读本页。这些信息旨在提供帮助，但如果你对任何内容有疑问或有问题，请加入 Documentation 论坛的讨论。

结构 - 通用原则

每个页面都应或多或少地完整解释一个主题。如果感觉某个页面变得太长，请尝试将其拆分为单独的页面。

并非每个页面都相同，但牢记以下几点可以帮助你以读者容易理解的方式组织页面内容：

以概述开头

以概述开头有助于在深入细节之前先介绍主题。概述通常不需要小节标题。

建立层级

想一想大多数用户想要实现什么，以及他们为什么会来到手册查找信息。将最常见任务的解决方案放在页面顶部；不太常用的信息可以放在底部。

逻辑地组织信息

相关概念应放在一起讨论。这有时可能要求将较少使用的功能与较常用的功能放在一起讨论，但这是可以的。

专注于用户任务，而不仅仅是 UI 组件

例如，“创建自定义调号”一节比名为“使用主面板”的一节更好。

标题

标题用于为页面上的信息提供结构和层级。

你输入的第一个小节标题将始终是一级标题。也请不要跳级（例如，在一级标题之后直接添加三级标题）。

标题级别 用途
一级标题 用于每个小节的开始。
二级标题 用于每个子小节的开始，以及介绍单步说明（即不需要列表时）。
三级标题 仅在需要额外子小节时谨慎使用。

尽量让你的标题以动词开头，例如“添加拍号”，而不是“拍号”。

内容

MuseScore 手册大致包含两类主要信息：描述性材料和面向目标的说明。

描述性材料

用于解释程序的不同方面。例如：

面板是包含可应用于乐谱的音乐符号的文件夹。MuseScore 的默认面板包含相关符号的集合，但你可以自定义面板以显示几乎任何类型的符号、线条或文本。

描述性材料往往比面向目标的说明更长、更“充实”，但我们仍要求你尽可能使用简单、平实的语言。

面向目标的说明

这些说明解释如何执行特定任务。说明应尽可能简短直接，通常采用编号列表的形式。例如，

要创建新面板：

  1. 打开面板选项卡
  2. 单击添加面板
  3. 单击创建自定义面板
  4. 为新面板命名，然后单击创建

请注意，我们对用户界面中的命名组件（包括菜单）使用加粗文本。键盘快捷键（如 Ctrl+S）使用 GitBook 的“键盘”样式呈现。

编写面向目标的说明时，请：

  • 只使用编号列表（不使用圆点列表）
  • 每条编号说明以动词开头
  • 每个编号项只写一项任务/指令

例如，不要这样写：

  1. 打开面板选项卡并单击添加面板

请这样写：

  1. 打开面板选项卡
  2. 单击添加面板

请务必在存在键盘选项的面向目标的说明中包含键盘选项。这对于提高程序的可访问性尤为重要。

非文字媒体的使用

鼓励使用非文字媒体作为文字描述的补充。这包括：

  • 动画 GIF
  • 用户界面相关部分的截图

创建动画 GIF

动画 GIF 相对于截图和视频有许多优势，因为它们能在最短时间内展示完成特定任务所需的操作序列。有许多工具可用于创建 GIF，但我们推荐以下工作流程，以确保图像清晰，同时保持尽可能小的文件大小（每个 GIF 最好小于 2MB）。

  • 只使用 MuseScore Studio 4 界面，并将其外观设置为带有蓝色高亮的深色模式（以在整个手册中保持一致）
  • 计划并演练你将使用的鼠标单击和键盘快捷键，力求在尽可能短的时间内演示所需步骤（最好少于 10 秒）
  • 使用 gifcap 等免费工具录制屏幕内容
  • 使用 KeyCastr 等免费工具记录按键（在需要时）
  • 只展示演示特定任务所需的 UI 数量
