样式指南

通用

大小写

所有文本都应使用句首大写。这包括所有段落、标题和页面标题。

GitBook 会将某些文本呈现为全大写，例如屏幕左侧目录中的组（即章节）标题。但是，在编辑此文本时，你应使用句首大写。

专有名词和缩写应根据相关主题的维基百科页面上使用的通行形式进行大写。

导入 MusicXML 文件。 :white_check_mark: MusicXML 要大写

自定义用户界面（UI）。 :white_check_mark: UI 要大写，而 用户界面 则不要

提供盲文和改良谱表记谱法。 :white_check_mark: MSN 要大写，而 盲文 则不要

日常用语中的缩写不应大写。

四分音符（aka crotchet）是一种音乐时值。 :white_check_mark: aka 不大写

UI 标签

在为用户编写说明时，MuseScore 用户界面中出现的文本应逐字复制（包括任何大小写），并以加粗高亮，不加引号。

按下暂不按钮。 :white_check_mark: 暂不 加粗，且大小写与应用程序中一致

UI 路径中的箭头

输入 -> 来描述子菜单或对话框层级中的路径。

GitBook 会将 -> 格式化为单个箭头字符，但在编辑模式下它会显示为单独的字符。由于箭头两侧的文本会以加粗样式显示（所有来自 UI 的文本都应如此），箭头也应保持加粗。每个箭头两侧各留一个空格。

选择 文件 -> 另存为 -> 保存副本... :white_check_mark:

取消勾选 样式 -> 音符 -> 缩短符干。 :white_check_mark:

圆点列表

圆点列表（即无序列表）用于非有序流程的列举内容。

如果一组圆点列表的内容不是完整的句子，则无需使用句号。

  • 力度记号
  • 变音记号
  • 演奏记号 :white_check_mark: 无句号

当圆点列表项是完整句子时，在每个句子末尾使用句号，即使只有一个句子。

  • 这是一个单句圆点列表项，末尾有句号。
  • 这是一个包含两个句子的列表项。每个句子后都加句号。 :white_check_mark: 完整句子需要句号

常见的模式是在圆点列表项开头使用加粗文本，后跟冒号。在这种情况下，冒号也应加粗，冒号后的第一个字符应大写。

  • 要点： 这是一个好示例。 :white_check_mark: 冒号加粗且“这”字要大写
  • 要点：这是一个坏示例。 :x: 冒号未加粗且“这”字未大写

编号列表

编号列表（即有序列表）用于必须按顺序完成的内容。对于如何执行任务的说明，尽量每个编号只写一句话，并在每句末尾使用句号。

  1. 想好要说什么。
  2. 用带句号的简短句子表达每一步。
  3. 完成列表。 :white_check_mark:

超链接

在适当的情况下，可以为普通文本中的关键词或短语添加超链接，文本的撰写应使链接在移除后依然通顺。一般来说，不应显示完整 URL。

观看教程视频。 :white_check_mark: 没有链接文本依然通顺

在此处观看教程。 :x: 如果移除链接，文本将不通顺

在 https://www.youtube.com/watch?v=z4Ecaaqwg8U 观看。 :x: 不要显示 URL

普通域名应像品牌名称一样大写。顶级域（TLD，例如 .com、.org、.co.uk 等）应省略，除非有充分理由保留。

在 Facebook 和 YouTube 上找到我们。 :white_check_mark: 这些热门网站省略 .com 顶级域

在 Audio.com 上聆听。 :white_check_mark: 顶级域是网站品牌的一部分

访问 MuseScore.org。 :white_check_mark: 顶级域是区分 MuseScore.com 所必需的

从 MuseHub.com 下载安装程序。 :white_check_mark: 特指该网站

在 MuseHub 中获取音色。 :white_check_mark: 指该应用（但链接到网站）

键盘快捷键

键盘快捷键应按如下格式排版：

按下 Shift+1—9。 :white_check_mark: 短横线 表示范围

按下 Ctrl+Shift++/-（Mac：Cmd+Shift++/-）。 :white_check_mark: 斜杠 表示可选

修饰键应按以下形式和顺序书写，各平台分别列出：

Windows/Linux：Win+Ctrl+Alt+Shift+Fn+... :white_check_mark:

Mac：Ctrl+Cmd+Option+Shift+Fn +... :white_check_mark:

在 Linux 特定的说明中，Win 键应写作 Super。

输入可打印字符的键应以该字符表示。

. , ; ' [ ] / \ - = ` 等。 :white_check_mark:

所有不可打印的键都应用其（可能是缩写的）名称引用，而不是符号。这包括光标键。

Space Backspace Del Ins Esc Return Up Down Left Right PgUp PgDn Home End Menu Caps Lock :white_check_mark:

输入的字符

输入的序列通常应排版为 行内代码，即使只有一个字符。

要输入重降号，请键入 bb。 :white_check_mark: 行内代码 （单个元素）

偶尔，也许更适合显示实际按下的键，将其排版为键盘快捷键而不是行内代码。

要输入重降号，请键入 B B。 :white_check_mark: 键盘按键 （每个键之间有空格）

结构

页面

你正在查看样式指南页面，它是关于本手册的子页面。

页面标题

页面标题应相对较短。理想情况下，标题应能容纳在屏幕左侧“目录”中的一行内，但这并不总是可行。请记住，页面标题在翻译成英语以外的其他语言时可能会明显更长。

保持页面标题简短的技巧：

  • 避免使用“乐谱”一词（例如“选择元素”，而不是“选择乐谱中的元素”）
  • 避免使用“MuseScore”一词（例如“升级”，而不是“升级 MuseScore Studio”）

子页面

使用子页面时，只能使用一层子页面。切勿创建子子页面。

父页面应使用非常简短的标题，因为其标题会出现在其所有子页面的 URL 中。

一般来说，我们更倾向于使用组而不是子页面，以避免在目录中嵌套。

组

组就像章节。它们在屏幕左侧的目录中以全大写显示（例如“INTRODUCTION”和“NAVIGATION”）。当前组名也会以超链接形式显示在主要内容区域每个页面标题的上方。

组名应使用句首大写——全大写样式由 GitBook 自动处理。

组的名称应非常简短。这是因为组名会出现在组内所有页面的 URL 中。

可以编辑组的 slug 使其短于实际组名。但是，一般来说不应这样做。相反，应使组名尽可能短。
